1. SYSTEM ACTORS OVERVIEW
========================================================================================================================

+----------------------------+-----------------------------------------------------------------------------------------+
| ACTOR NAME                 | ROLE DESCRIPTION & OPERATIONAL RESPONSIBILITIES                                         |
+----------------------------+-----------------------------------------------------------------------------------------+
| 1. ADMIN / OWNER           | Primary administrative actor (landlord, property owner, manager).                       |
|    (Property Administrator)| Has full operational authority over room inventory, bed allocation, tenant approvals,  |
|                            | monthly billing, receipt verification, maintenance management, CCTV security feeds,     |
|                            | and business revenue analytics.                                                         |
+----------------------------+-----------------------------------------------------------------------------------------+
| 2. TENANT / RESIDENT       | Primary client actor (resident boarder or prospective applicant).                       |
|    (Boarder / Renter)      | Uses the self-service portal to browse/apply for rooms, review tenancy details, view    |
|                            | itemized monthly invoices, submit payments with receipt uploads, submit repair tickets, |
|                            | chat with the landlord, and read property notices.                                      |
+----------------------------+-----------------------------------------------------------------------------------------+
| 3. AUTOMATED CRON ENGINE   | Secondary background system actor (Node-cron automated engine).                         |
|    (System Scheduler)      | Automatically runs scheduled monthly tasks: generates recurring rent & utility bills,   |
|                            | calculates overdue accounts, and logs system audit activities without manual trigger.   |

4. DETAILED USE CASE DESCRIPTIONS
========================================================================================================================

------------------------------------------------------------------------------------------------------------------------
[UC-01] LOGIN & AUTHENTICATE TO PORTAL
------------------------------------------------------------------------------------------------------------------------
- Primary Actors  : Admin / Owner, Tenant / Resident
- Pre-conditions  : User account exists with verified credentials in the database.
- Trigger         : User visits the web app and enters Email and Password.
- Main Flow       :
  1. System verifies email existence and compares hashed password using bcrypt.
  2. System issues a cryptographically signed JSON Web Token (JWT) with user ID and role.
  3. Client stores token securely in localStorage / HTTP cookies.
  4. Role Guard redirects Admin to '/admin/dashboard' or Tenant to '/tenant/dashboard'.
- Post-conditions : User authenticated with active session and authorized route access.

------------------------------------------------------------------------------------------------------------------------
[UC-02 & UC-03] REGISTER ACCOUNT & APPLY FOR ROOM
------------------------------------------------------------------------------------------------------------------------
- Primary Actor   : Tenant Applicant
- Pre-conditions  : Prospective tenant does not yet have an active account.
- Main Flow       :
  1. Applicant fills out signup form (Full Name, Email, Password, Mobile Number).
  2. Applicant inputs emergency contact details (Contact Person, Relation, Emergency Phone).
  3. Applicant browses list of available rooms/beds and selects desired unit (e.g., Room 203).
  4. System creates new user entry with status 'Pending' and links requested room_id.
  5. Notification alert sent to Admin's Urgent Action Center.

------------------------------------------------------------------------------------------------------------------------
[UC-04] REVIEW & APPROVE/REJECT TENANT APPLICATIONS
------------------------------------------------------------------------------------------------------------------------
- Primary Actor   : Admin / Owner
- Pre-conditions  : Pending tenant applications exist in the system.
- Main Flow       :
  1. Admin navigates to Tenants -> Approvals tab.
  2. Admin inspects applicant details, requested room, and contact info.
  3. Admin clicks 'Approve': System marks user status as 'Active', assigns bed space, updates room occupancy count.
  4. (Alternative) Admin clicks 'Reject': System updates status to 'Inactive' and frees room slot.

------------------------------------------------------------------------------------------------------------------------
[UC-06, UC-07 & UC-08] ROOM, BED & PRICING MANAGEMENT
------------------------------------------------------------------------------------------------------------------------
- Primary Actor   : Admin / Owner
- Main Flow       :
  1. Admin adds or edits room records (Room Number, Floor Level, Max Bed Capacity, Type).
  2. Admin tags amenities (Air Conditioning, Private Bathroom, High-speed Wi-Fi, Balcony).
  3. Admin configures base monthly rental rate.
  4. Admin assigns or reassigns active tenants to specific beds. Room status dynamically transitions:
     'Available' -> 'Partially Occupied' -> 'Occupied' (Full) -> 'Maintenance'.

------------------------------------------------------------------------------------------------------------------------
[UC-09] VIEW VISUAL FLOOR & ROOM MATRIX
------------------------------------------------------------------------------------------------------------------------
- Primary Actors  : Admin / Owner, Tenant / Resident
- Description     : Interactive, color-coded floor map showing every room and occupied bed in the building.
                    Allows clicking into individual units to view current tenants, amenities, and vacancies.

------------------------------------------------------------------------------------------------------------------------
[UC-10 & UC-11] TENANT MOVE-OUT & LEASE TERMINATION
------------------------------------------------------------------------------------------------------------------------
- Primary Actors  : Tenant (initiates UC-10), Admin (processes UC-11)
- Description     : Under RentTrack's flexible stay model, tenants can file a Notice to Vacate at any time.
                    Admin processes move-out inspection, verifies that pending bills are settled, marks tenant as
                    'Moved Out', releases the bed space to 'Available', and logs a move-out activity item.

------------------------------------------------------------------------------------------------------------------------
[UC-12 & UC-14] MONTHLY BILLING & UTILITY INVOICING
------------------------------------------------------------------------------------------------------------------------
- Primary Actors  : Automated Cron Engine (UC-12), Admin / Owner (UC-14)
- Description     : 
  * Automated Node-cron runs on the 1st of each month to auto-generate itemized monthly invoices for all active boarders.
  * Admin can also manually generate custom bills or adjust itemized costs: Base Rent, Water Bill, Electricity Bill,
    and Ancillary/Wi-Fi charges.
  * System dynamically computes total amount due and sets status to 'Unpaid'.

------------------------------------------------------------------------------------------------------------------------
[UC-15, UC-16 & UC-17] VIEW BILLS & SUBMIT PAYMENT PROOF
------------------------------------------------------------------------------------------------------------------------
- Primary Actor   : Tenant / Resident
- Description     :
  1. Tenant views outstanding balance on dashboard and reviews itemized charges.
  2. Tenant clicks 'Pay Now' and selects payment channel: GCash, Maya, Bank Transfer, or Cash.
  3. Tenant uploads photo/screenshot of transaction receipt and enters reference number (e.g., #TX-20261013-0033).
  4. System uploads receipt file via Multer, updates bill status to 'Pending Verification', and alerts Admin.

------------------------------------------------------------------------------------------------------------------------
[UC-18] VERIFY PAYMENT RECEIPT & SETTLE BALANCE
------------------------------------------------------------------------------------------------------------------------
- Primary Actor   : Admin / Owner
- Description     :
  1. Admin opens Pending Verification queue or Payment Inspector modal.
  2. Admin reviews uploaded receipt image, verified payment amount, and bank reference number.
  3. If valid: Admin clicks 'Approve' -> System records payment transaction, deducts bill balance, marks bill as 'Paid'
     (or 'Partial'), updates collection analytics, and logs a verified payment activity.
  4. If invalid: Admin clicks 'Reject' with feedback notes -> Bill reverts to 'Unpaid' and tenant is notified.

------------------------------------------------------------------------------------------------------------------------
[UC-19, UC-20 & UC-21] MAINTENANCE TICKETING & KANBAN
------------------------------------------------------------------------------------------------------------------------
- Primary Actors  : Tenant (UC-19, UC-20), Admin (UC-21, UC-22)
- Description     :
  1. Tenant logs issue with Category (Plumbing, Electrical, Carpentry, Appliance, Internet, General) and Priority.
  2. Tenant optionally attaches a clear photo of the damage/leak.
  3. Ticket appears on Admin's live Kanban board across columns: [Pending] -> [In Progress] -> [Resolved].
  4. Admin assigns technician and updates status. Changes reflect live on Tenant dashboard.
  5. Tenant can cancel ticket while in 'Pending' status.

------------------------------------------------------------------------------------------------------------------------
[UC-24 & UC-25] BROADCAST ANNOUNCEMENTS
------------------------------------------------------------------------------------------------------------------------
- Primary Actors  : Admin (creator), Tenant (reader)
- Description     : Admin posts property-wide announcements (e.g., scheduled maintenance, holiday curfew, water outage).
                    Includes priority tags (Standard, Important, Urgent). Displays on tenant dashboard banner.

------------------------------------------------------------------------------------------------------------------------
[UC-26] ONE-TO-ONE DIRECT CHAT & MESSAGING
------------------------------------------------------------------------------------------------------------------------
- Primary Actors  : Admin / Owner, Tenant / Resident
- Description     : Integrated real-time messaging channel allowing tenants to communicate directly with the landlord
                    for inquiries, payment clarifications, and urgent requests. Includes unread badges.

------------------------------------------------------------------------------------------------------------------------
[UC-27 & UC-28] MULTI-CHANNEL CCTV VIDEO SURVEILLANCE
------------------------------------------------------------------------------------------------------------------------
- Primary Actor   : Admin / Owner
- Description     : Live virtual security matrix streaming 12 property surveillance feeds (Main Gate, Lobby, Parking,
                    Hallways, Rooftop, Elevator, Emergency Exits). Supports 2x2, 3x3, and 4x4 matrix grid switcher,
                    live timecode overlay, camera FPS diagnostics, and single-click fullscreen camera inspection.

------------------------------------------------------------------------------------------------------------------------
[UC-29, UC-30 & UC-31] BUSINESS INTELLIGENCE & AUDIT
------------------------------------------------------------------------------------------------------------------------
- Primary Actor   : Admin / Owner
- Description     : Real-time analytical KPIs showing Total Invoiced vs. Collected Revenue vs. Outstanding Balances
                    (Recharts ComposedChart), collection rates, occupancy rates, Urgent Action Center (4 priority items),
                    and Recent Activity feed (6 items visible, 2-line concise layout with 27-char wrap limit).

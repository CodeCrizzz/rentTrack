                    RENTTRACK - ACTIVITY LOGS SYSTEM WORKFLOW
================================================================================

1. EXECUTIVE OVERVIEW & OBJECTIVE
--------------------------------------------------------------------------------
The Activity Logs feature serves as an immutable, real-time audit trail and 
centralized operational ledger for the boarding house management system.
It aggregates, normalizes, and presents cross-domain system events across:
  - Financial transactions (Payments, bill verifications)
  - Resident lifecycle (Applications, approvals, move-ins, move-outs)
  - Facility operations (Maintenance repair tickets, status resolutions)
  - Communications (Direct tenant inquiries, emergency broadcasts)

NOTE: This feature is exclusively accessible to authorized Administrators.

4. STEP-BY-STEP OPERATIONAL WORKFLOW
--------------------------------------------------------------------------------

STEP 1: EVENT GENERATION (Background/User Action)
  - Whenever an action occurs in the portal (e.g., tenant pays rent, submits a
    plumbing ticket, or checks out), the backend persists the transaction into
    its native database table.

STEP 2: AGGREGATION & NORMALIZATION (Backend on Request)
  - When the Admin accesses /admin/activity-logs, the client sends:
      GET /api/admin/activity-logs (Bearer Token Authorization)
  - The server verifies that req.user.role === 'admin'.
  - The controller runs 6 parallel queries against the PostgreSQL database.
  - Raw table rows are transformed into a normalized activity object structure
    with uniform timestamps, action links, and human-readable descriptions.
  - The composite array is sorted descending by date and sent as JSON.

STEP 3: RENDERING & INTERACTION (Admin Interface)
  - The admin page displays 4 summary KPI tiles at the top.
  - The admin can filter by category (e.g., view only Payments).
  - The admin can filter by timeframe (e.g., view only Today's activity).
  - The admin can type keywords into the search box to find specific tenant
    names, reference numbers, or room numbers.
  - Each log row contains a direct link:
      * Clicking a payment log navigates to /admin/billing for that tenant.
      * Clicking a maintenance log navigates to /admin/requests.
      * Clicking an applicant log navigates to /admin/tenants approvals.
      * Clicking a message log navigates to /admin/chat.

STEP 4: AUDIT EXPORT
  - The admin clicks "Export CSV" to instantly generate and download a standard
    CSV spreadsheet containing all currently filtered records for external
    record-keeping or compliance.


5. STRICT ACCESS CONTROL & BOUNDARIES
--------------------------------------------------------------------------------
- Admin Portal: Accessible via Sidebar ("Activity Logs") and route /admin/activity-logs.
- Tenant Portal: Strictly omitted. No navigation items, links, or components exist.
- Network Security: API endpoint /api/admin/activity-logs is guarded by both
  token verification (protect) and role verification (adminOnly).
- Client Security: AdminLayout redirects unauthorized tenant sessions to
  /tenant/dashboard automatically.
